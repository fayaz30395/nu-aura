## Why this critical set (23 routes)

CRITICAL = a route a real user must be able to use for the product to be viable. Marked critical:
- **Auth**: `/auth/login`, `/auth/logout` — without these no one gets in or out.
- **Landing**: `/` — first thing an unauthenticated visitor sees; gateway to login.
- **Dashboards**: `/dashboard`, `/me/dashboard` — the default post-login destination.
- **Employee list/detail**: `/employees`, `/employees/[id]` — core HR record, referenced from nearly every other module.
- **Leave apply/approve**: `/leave`, `/leave/apply`, `/leave/approvals`, `/leave/my-leaves` — the highest-frequency self-service + manager-action workflow in any HRMS.
- **Attendance**: `/attendance`, `/attendance/my-attendance` — daily-use, every employee.
- **Payroll view**: `/payroll/payslips`, `/me/payslips` — employees checking pay is non-negotiable.
- **Profile**: `/me/profile` — every user's own record.
- **Sub-app main navigation entry points** (per the brief, one per sub-app plus its switcher tile): `/app/hrms`, `/app/hire`, `/app/grow`, `/app/fluence` (the 4 switcher landing pages) and `/recruitment` (Hire), `/learning` (Grow), `/fluence` (Fluence) as each sub-app's own primary hub page.

Everything else — admin config screens, reports, settings sub-pages, second-order workflow steps (offer letters, contracts, travel, loans, surveys, wellness, etc.) — is SECONDARY: valuable, but the product is usable without a first-time user ever touching them. This is a judgment call, not a formula; the intent is to keep the critical set to what actually blocks day-one usability, not everything that has a page.
