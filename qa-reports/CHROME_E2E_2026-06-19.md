## Bug Register

### 🔴 CRITICAL — Blocks Real-User Go-Live

**SEC-001: `DEMO_CREDENTIALS_ENABLED=true` in production**
- Login page publicly lists all 8 demo accounts with cleartext password `Welcome@123`
- One-click SUPER_ADMIN grants full tenant access to any visitor
- **Root cause (code-confirmed):** `NEXT_PUBLIC_DEMO_MODE=true` in Vercel env → renders demo panel; Railway backend `render` profile defaults `DEMO_CREDENTIALS_ENABLED=true`
- **Fix:** Two changes required:
  1. Set `NEXT_PUBLIC_DEMO_MODE=false` in Vercel project environment variables
  2. Set `DEMO_CREDENTIALS_ENABLED=false` in Railway service variables
- Neither requires redeploy (env changes take effect on next request)
- **Status:** Config-only fix, no code change needed

### 🟡 MEDIUM — Fix Before Full Rollout

**BUG-MED-001: `/leave/admin` → 404 (partial fix)**
- `/leave/admin/carry-forward` now works correctly ✅
- `/leave/admin` index still 404s — no `app/leave/admin/page.tsx` exists
- **Fix:** Either add an index page or redirect `/leave/admin` → `/leave/admin/carry-forward`

**BUG-MED-004: `/auth/logout` → 404**
- Logout via the UI dropdown works (JS-driven, calls API directly)
- But `/auth/logout` as a direct URL 404s — **code-confirmed:** no `app/auth/logout/page.tsx` exists
- Risk: e-sign invalid token flow or external redirects that target this URL leave user on 404
- **Fix:** Add a minimal `app/auth/logout/page.tsx` that calls the logout API and redirects to `/auth/login`

**BUG-MED-005: Demo login role badge mismatch (Saran V)**
- Login card shows "Saran V — EMPLOYEE" (configured in `app/auth/login/page.tsx:90-96`)
- After login, header displays "Saran V — HR ADMIN" (actual DB role for `saran@nulogic.io`)
- **Code-confirmed:** This is a seed-data inconsistency in the database, not a UI rendering bug
- **Security note:** No security impact — RBAC correctly applies the HR_ADMIN role from DB; no EMPLOYEE demo account is actually testable via the demo panel
- **Fix:** Either update the DB seed so `saran@nulogic.io` has EMPLOYEE role, or update the login card config to show HR_ADMIN

**NEW-001: `/fluence/articles` → 404**
- First-pass swarm reported `/fluence/articles` as passing; extended test confirms 404
- The route may have been renamed to `/fluence/blogs` in a prior refactor but the old URL was not redirected
- **Fix:** Add redirect from `/fluence/articles` → correct route, or reinstate the page if it was accidentally removed

### 🔵 LOW — Polish / UX

**BUG-LOW-001: "Unlock NU-Grow" banner inside NU-Grow for SUPER_ADMIN**
- **Code-confirmed:** `NavPanel.tsx:211-230` renders the upsell banner unconditionally — no plan-status check, no `hasGrowAccess` flag, no subscription tier gate
- Appears even when user is SUPER_ADMIN with "All Modules Active — Pro Plan" badge, actively inside NU-Grow
- **Fix:** Gate the banner render behind a plan check: `if (!hasGrowAccess) { <UpsellBanner/> }`

**BUG-LOW-002: RBAC denial — inconsistent UX (partial improvement noted)**
- **Pattern A (some admin routes):** Shows inline "Access Restricted — You don't have permission to view this page" component. User stays on the blocked URL. Has "Go to Home" button. ✅ Reasonable UX.
- **Pattern B (other routes):** Redirects to `/me/dashboard?denied=1` or `/recruitment?denied=1`. **Code-confirmed:** `searchParams.get('denied')` has 0 consumers across all app pages — no toast, banner, or notification fires. User sees their dashboard with no explanation.
- **Fix:** Add a client-side listener for `?denied=1` in the app shell that fires a toast: `"You don't have access to that page"`

**BUG-LOW-003: Missing demo accounts for FINANCE_ADMIN / PAYROLL_ADMIN**
- 3 of 8 demo accounts are TEAM_LEAD (Mani S, Gokul R, Dhanush A)
- Zero accounts for FINANCE_ADMIN or PAYROLL_ADMIN roles
- Payroll run approval and finance workflows cannot be demoed from the quick-login panel

**BUG-LOW-004: Attendance timezone — avg check-in mismatch**
- Dashboard clock shows IST; attendance avg check-in values show mismatch with "Late" tags
- Known timezone drift issue (OBS-001 from prior sessions)
