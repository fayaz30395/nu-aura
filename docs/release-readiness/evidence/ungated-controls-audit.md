Static code reading only; nothing was run.

Scope: 216 page.tsx files under frontend/app in the HR/admin/ops modules were screened by grep (action words vs. gate words). About 70 were read in detail. Roles are from the Flyway seeds (V66, V107, V174-176, V289-V307); later migrations were not exhaustively checked, so "roles" are best-effort. Most pages (employees, leave, assets, announcements, helpdesk, expenses list, loans, probation, offboarding, onboarding list, shifts, payroll, performance, training, benefits, holidays) already gate controls correctly and are not listed.

Pattern: the page-level gate uses a VIEW/READ permission, the controls inside have no gate of their own, and the API needs MANAGE/APPROVE/UPDATE.
