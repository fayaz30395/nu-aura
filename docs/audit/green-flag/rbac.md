# RBAC-01 — Authorization End-to-End Audit (Green-Flag)

Repo: `nu-aura` · Auditor: rbac agent · Scope: backend `@RequiresPermission` enforcement, permission-string ↔ seed integrity, frontend guard layering, horizontal (IDOR) access, privilege escalation, tenant boundary.

Method: paren-balanced parse of all 180 `*Controller.java` (1,755 mapping annotations); cross-ref of every permission string used in code against canonical seed (`V96__canonical_permission_reseed.sql` + later migrations) and `HrmsPermissionInitializer`; service-layer ownership-check trace on `{employeeId}` endpoints; review of role/permission grant paths and `SecurityConfig` `permitAll` allowlist.

By design (NOT flagged): SuperAdmin bypass (audited & logged in `PermissionAspect`); My Space items without `requiredPermission` (self-service) — but their API ownership WAS checked.

## Verified-secure (no finding)

- **Privilege escalation** — `RoleManagementService.assignRolesToUser` calls `validateNoPrivilegeEscalation` (only SuperAdmin may assign `SUPER_ADMIN`) and all 4 permission-grant paths call `validateNoPrivilegedPermissionGrant` (only SuperAdmin may grant `SYSTEM:ADMIN`, `PERMISSION:MANAGE`, `PLATFORM:MANAGE`). `RoleController` create/update/grant all use `ROLE_MANAGE` with `revalidate=true`. A TenantAdmin cannot self-elevate to SuperAdmin.
- **Employee IDOR** — `EmployeeController` `/{id}` GET and update enforce `enforceEmployeeViewScope` / `enforceEmployeeUpdateScope` (VIEW_ALL > DEPARTMENT > TEAM > SELF) at the controller. Solid reference implementation for RBAC-1/2.
- **Payroll IDOR** — every `/payslips/employee/{employeeId}` + salary-structure endpoint calls `validateEmployeeAccess(employeeId, permission)`; sensitive ops use `revalidate=true`.
- **Empty-annotation guard** — `PermissionAspect` denies any `@RequiresPermission` with no codes (CRIT-1), preventing accidental allow-all.
- **Tenant boundary** — service queries consistently use `findBy...AndTenantId`; `SecurityContext.hasPermission` reads `getCurrentTenantId()` context; no permission check observed that ignores tenant_id.

## Summary (5 lines)

1. No CRITICAL unguarded write endpoints: all 46 unguarded mappings are intentional public/auth/webhook routes with their own token / API-key / signature auth, individually verified.
2. Two HIGH horizontal-access (IDOR) flaws: Benefits (RBAC-1, 6 endpoints) and Leave-balance (RBAC-2) accept `*_VIEW_SELF`/`VIEW_TEAM` but the service layer scopes only by tenant — any employee reads colleagues' PII/financial data by changing the path UUID.
3. One HIGH permission-string mismatch: `StatutoryContributionController` + `TDSController` use underscore literals `"STATUTORY_VIEW/MANAGE"` that never match the colon-seeded codes → silent permanent 403 for everyone but SuperAdmin (RBAC-3).
4. MEDIUM: `TRAINING:UPDATE/DELETE`, `PROJECT:DELETE`, `HELPDESK:TICKET_*`, `SURVEY:*` codes are referenced but unseeded, surviving only via the MANAGE-implies-all hierarchy fallback (RBAC-4); frontend route guards are client-side only (RBAC-5, defense-in-depth).
5. Escalation, role-assignment, employee/payroll IDOR, and tenant isolation are correctly implemented — fix RBAC-1/2/3 before green-flag.
