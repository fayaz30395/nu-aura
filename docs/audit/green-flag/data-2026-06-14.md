## What's solid (verified this pass, no action)

- **Leave balance integrity:** create/update/approve/reject/cancel all reserve-before-save inside one `@Transactional`; pending reservation, deduction and release amounts consistently mirror the half-day (0.5) vs full-range logic; balance mutations go through `getOrCreateBalanceForUpdate` (PESSIMISTIC_WRITE).
- **Expense state machine:** `updateExpenseClaim`/`deleteExpenseClaim` guard `status == DRAFT`; workflow `onApproved`/`onRejected` re-check `SUBMITTED/PENDING_APPROVAL`; direct approve cancels live workflow execution (BA-5b); summary range capped (M-17); every transition audited.
- **Loan state machine:** approve/reject guard `PENDING`, disburse guards `APPROVED`, activate guards `DISBURSED`, repayment guards `ACTIVE/DISBURSED`, cancel blocks `ACTIVE/CLOSED` — no invalid transitions; ownership enforced via `enforceLoanAccess`; repayment clamps outstanding to ≥0; `@Positive` on `RecordRepaymentRequest.amount`/`CreateLoanRequest.principalAmount`. (Gaps: audit + idempotency — DATA-14/15.)
- **Attendance:** check-in rejects open-session / already-completed days; checkout validates time ordering and lookback. (Gap: dup-day constraint — DATA-16.)
- **Payroll:** period advisory lock + `findByTenantIdAndPeriodForUpdate` + V283 unique index; status-machine guards; APPROVED-only leave-day filter (REG-1) holds.
- **Optimistic locking everywhere:** `BaseEntity.@Version` applies to all entities incl. loan/expense/leave/attendance; conflicts → 409 via `GlobalExceptionHandler`.
- **Tenant isolation:** all examined create/update/delete/read paths scope by `tenantId`; `TenantEntityListener` blocks cross-tenant persist/update/delete; RESTRICTIVE FORCE RLS.
