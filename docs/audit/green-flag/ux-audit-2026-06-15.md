## Design System Inventory

### Typography Scale

Defined across three files:
- `frontend/styles/tailwind-presets.ts` — semantic Tailwind class bundles (pageTitle, sectionTitle, cardTitle, label, body, stat)
- `frontend/styles/mantine-theme.ts` — Mantine component overrides
- `frontend/app/globals.css` — CSS custom property definitions

**Font families:**
- Body: `Open Sans` via `--font-sans` / `var(--font-body)`
- Display / headings: `Montserrat` via `--font-display` / `var(--font-head)`
- Mono: `Roboto Mono` via `--font-mono`

**Size tokens (CSS vars):**
- `--aura-title-size: 28px` — page titles, mapped to `.text-aura-title`
- `--aura-stat-size: 29px` — KPI values
- `--aura-micro-size: 10.5px` — table headers, micro-labels (uppercase, 0.1em tracking)
- Tailwind compactTheme: `text-2xl` (pageTitle), `text-xl` (sectionTitle), `text-base` (cardTitle), `text-xs` (label / labelMicro), `text-sm` (body)

**Gap identified:** Token split across 3 files creates drift risk. Confirmed: 675 pages use raw `text-xl`/`text-2xl`/`text-3xl` classes while only 126 pages use the `text-aura-*` design-system tokens. Most pages bypass the token layer.

### Color Palette

**Brand / Accent:**
- `--accent: #2952A3` (NU-AURA Blue, hue ~228), 10-step scale in `globals.css` and `mantine-theme.ts`
- Light-mode primary shade: step 7 (#2952A3); dark-mode: step 4 (#6884dc)
- NULogic brand gradient: `#ED3027 → #b53a86 → #7B469B`

**Semantic status tokens (complete set):**
- Success: `--ok-bg / --ok-fg / --ok-bd`
- Warning: `--warn-bg / --warn-fg / --warn-bd`
- Error: `--err-bg / --err-fg / --err-bd`
- Info: `--info-bg / --info-fg / --info-bd`
- Neutral: `--neutral-bg / --neutral-fg / --neutral-bd`

**Chart tokens:** `--chart-1` through `--chart-5` plus `--chart-axis`

**Product accent tokens:** `--prod-hrms / --prod-hire / --prod-grow / --prod-fluence`

**Gap identified:** Dual naming system detected. CSS variables use two incompatible naming conventions:
- Aura spec names: `--text-1`, `--text-2`, `--text-3`, `--surface`, `--border-soft`
- Legacy Studio Slate names: `--text-primary`, `--text-secondary`, `--text-muted`, `--bg-card`, `--border-subtle`
- Both are live in the codebase: 1,783 references to `--text-primary/secondary` vs 1,893 to `--text-1/2/3`. Both resolve in globals.css via aliases, but components mixing both systems are resistant to future token refactors.

### Spacing System

Strict 8px grid defined in `tailwind-presets.ts`. Banned classes: `gap-3, p-3, p-5, gap-5, space-y-5, space-y-3`.
CSS vars: `--s-1 (4px)` through `--s-12 (48px)`.

**Gap identified:** 0 confirmed inline `style={{ }}` violations (grep confirmed no raw inline style pixel values). The spacing discipline appears enforced by convention rather than linting — no automated enforcement found.

### Component Library Depth

**Custom components (fully designed, not Mantine defaults):**
- `Card` (with padding prop, hover-lift, press-scale, variant system)
- `Button` (variants: primary/ghost/outline/destructive, sizes sm/md/lg/icon-sm)
- `Stat` (full props: label, value, caption, icon, iconTone, delta, deltaDir, spark, foot)
- `StatusBadge` (domain-driven color mapping)
- `EmptyState` (icon + title + description pattern)
- `Skeleton` (consistent loading state)
- `DataTable`, `ResponsiveTable`, `EditableCell` (table variants)
- `MobileBottomNav` (mobile bottom navigation)
- `AdvancedFilterPanel`, `TableFilterBar`
- `PremiumMetricCard`, `AnimatedCard`, `StatCard`, `DashboardGrid`
- `Ring`, `Donut`, `Stagger`, `Reveal`, `PageTransition` (chart and motion primitives)
- `ConfirmDialog`, `Modal`, `FileUpload`, `Switch`
- `Segmented`, `Badge`, `Callout`, `Tabs`

**Mantine components used with customization (via theme):**
- All form inputs (TextInput, Select, MultiSelect, Autocomplete, Textarea, TagsInput) — 36px height enforced globally
- `Table`, `Modal`, `Drawer`, `Menu`, `Popover`, `Tooltip`, `Notification`, `Pagination`, `Alert`

**Mantine components used without significant customization:**
- `Loader`, `Divider`, `SegmentedControl`, `AppShell`

**Missing primitives identified:**
- No shared `Avatar` component — leave page implements `LeaveAvatar` inline; attendance, employee pages implement their own variants (`frontend/app/employees/_components/avatar.ts` is a utility, not a component)
- No `PageHeader` layout primitive — each page assembles its own header pattern
- No `SectionHead` shared primitive — payroll page defines it locally; other pages reimplement the same pattern inline

### Animation / Motion Strategy

Framer Motion used consistently via `PageTransition`, `Reveal`, `Stagger`, `StaggerItem` wrappers in `frontend/components/motion/`. Single EASE constant pattern used on leave page: `[0.16, 1, 0.3, 1]`. BentoHeroBars decorative animation is particularly polished. Coverage: 118 of 270 page files use motion primitives (44%).

**Gap:** 152 pages (56%) lack motion wrappers entirely — creates jarring contrast between "premium" pages (leave, payroll) and bare pages (many admin CRUD pages). Inconsistent motion discipline is visible during navigation.

### Icon Set

Lucide React throughout. Standardized sizes in `tailwind-presets.ts`: `h-8 w-8` (page/card header), `h-10 w-10` (stat card), `h-5 w-5` (card inline), `h-4 w-4` (button/badge). Some Tabler Icons present in older components.

### Top 5 Debt Items by Impact

1. **Card API split (345 files use old CardContent/CardHeader vs 48 use new padding prop)** — biggest single cause of visual inconsistency. Old API uses different padding (`p-6 pb-2` for CardHeader, `p-6` for CardContent) producing spacing that differs from the design system's 4-step grid.

2. **CSS variable naming drift (dual --text-primary vs --text-1 system)** — 1,783 uses of legacy names vs 1,893 of Aura names. The two systems are aliased in globals.css but future dark-mode changes or rebrand must update two systems simultaneously.

3. **Typography bypassing token layer (675 raw Tailwind size classes vs 126 design-system tokens)** — pages with `text-xl font-bold` look slightly different from pages with `text-aura-title` because `text-xl` is 20px vs `--aura-title-size: 28px`.

4. **Missing Avatar primitive** — used in at least 4 different page-local implementations. Minor but contributes to visual inconsistency in user-facing contexts (leave requests, employee cards).

5. **Motion coverage gap (56% of pages have no PageTransition/Reveal wrapper)** — CRUD-heavy admin pages have no entrance animation, creating a qualitative gap vs ESS pages.

## Page-by-Page Deep Dives

### Page 1: Employee Dashboard (`/dashboards/employee/page.tsx`)

**What it does:** The primary self-service landing page for individual employees. Shows attendance stats, leave balances, career goals, upcoming events, and quick actions.

**Visual Hierarchy Quality: 7/10**
Four stat cards at the top establish the KPI hierarchy correctly. The 3-column content grid (2 wide + 1 sidebar) is sound. However, the sidebar "Quick Actions" card is a list of 5 outline buttons with no visual differentiation — it reads as a feature list, not a navigation affordance. The "Career Progress" card mixes a 2x2 mini stat grid with a goal list, creating two visual languages in one card.

**Information Density: Right (slightly below)**
The page carries the correct amount of information for a daily entry point. The attendance trend chart and recent history table are well-prioritized. The "Upcoming Events" card could carry more events (shows max 5) or provide a mini calendar view to justify its position.

**Navigation Clarity: 6/10**
"Mark Attendance" (outline) vs "Apply Leave" (primary) in the header is sensible. However, within the "Quick Actions" card, 5 equal-weight outline buttons lack visual hierarchy. A user scanning for "payslips" must read every label. The buttons should use iconography + labeling with primary/secondary grouping.

**Empty/Loading/Error State Quality: 8/10**
Skeleton layout matches the real layout closely. `EmptyState` used correctly in chart and history sections. Error state shows a warning banner with a retry action — correct pattern. Minor: the error state still renders the stat card placeholders with "--" values which is good degraded experience.

**Mobile Responsiveness: 6/10**
2-column stat grid on mobile (`grid-cols-2`) is acceptable but the 48px padding cards compress too tightly on 375px viewports. The `lg:col-span-2` / sidebar grid collapses to single column on mobile — sidebar comes after main content (correct stacking order).

**Enterprise-Grade Feel: 7/10**
Clean, token-driven, with consistent use of design system colors. The `w-12 h-12 rounded-xl` icon tiles in stat cards look polished. Degrades gracefully. Main gaps: Quick Actions card feels like a UI placeholder rather than a designed feature, and the absence of motion makes this page feel static compared to the Leave page.

**First-time User Issues:**
1. "Mark Attendance" button appears in the top-right but there is no indication of whether attendance is already marked today — a user returning to the page cannot tell if they already punched in without reading the attendance history table.
2. "Career Progress" card shows count numbers (e.g., "3 Active Goals") but clicking them has no obvious navigation trigger — no hover state on the mini stat tiles reveals they are clickable.
3. The leave balance progress bars use `balance.colorCode` inline styles for colors, meaning the colors come from the database rather than the design token system. A user in dark mode may see a low-contrast leave type color that was configured for light mode only.

**Specific Code Improvements:**

| Issue | File | Line | Fix |
|---|---|---|---|
| Attendance today indicator absent — no "You're clocked in" / "Not yet marked" banner | `dashboards/employee/page.tsx` | L197–215 | Add a conditional status chip next to "Mark Attendance" based on `data.attendanceSummary.recentHistory[0]` matching today's date |
| Career mini-stat tiles are not clickable/navigable despite linking to /performance | `dashboards/employee/page.tsx` | L402–440 | Wrap each `div.text-center` tile in a `Link href="/performance"` with `hover:bg-accent-100` interactive state |
| Quick Actions card — 5 equal-weight buttons, no hierarchy | `dashboards/employee/page.tsx` | L588–636 | Split into primary actions (Apply Leave, Mark Attendance as `variant="primary"`) and secondary links (`variant="ghost"`) with a divider |

**Priorities:** Today indicator = Critical, Career tiles = High, Quick Actions = High

### Page 2: Leave (`/leave/page.tsx`)

**Visual Hierarchy Quality: 9/10**
This is the best-designed page in the codebase. The leave balance rings (4 ring charts), pending requests sidebar, and full-month calendar create a clear information hierarchy at a glance. The Bento navigation grid at the bottom provides context-aware routing (hero adapts to approver vs requester role). Motion is thoughtful — staggered entrance, single EASE constant, decorative BentoHeroBars animation.

**Information Density: Right**
The page shows the right data without overloading. The three-panel layout (balances left, calendar right) mirrors how employees actually think about leave: "how much do I have" and "when should I take it."

**Navigation Clarity: 9/10**
Segmented "Attendance | Leave" toggle at top-right is an elegant context switch. The Bento tiles at the bottom provide clear navigation to sub-functions with role-aware visibility (canApprove, canViewTeam, canRequest). The hero card adapts based on the user's most urgent action — a strong pattern.

**Empty/Loading/Error State Quality: 9/10**
Skeletons match the exact layout of the real data (2-column ring grid, list rows). Error banner is styled correctly with role="alert" and aria-live="polite". The attention strip (low leave warning) is well-designed. Minor: "No balances for this year yet" empty state has no action button.

**Mobile Responsiveness: 8/10**
`grid-cols-1 lg:grid-cols-3` collapses cleanly. Calendar renders at mobile widths using the same grid but the `min-h-[78px]` calendar cells shrink correctly.

**Enterprise-Grade Feel: 9/10**
Premium. The ring chart, bento layout, Framer Motion staggering, and contextual hero card put this page at Rippling / Notion quality. The BentoHeroBars decorative element is a standout.

**First-time User Issues:**
1. The balance rings show "X used · Y total" but there is no tooltip or overlay explaining what types of leave can be requested under each type — a new employee may not know which ring corresponds to which policy.
2. The `LeaveAvatar` in PendingRequests renders the leave type name's initials (e.g., "CL" for "Casual Leave") as if it were a person avatar — a first-time user may interpret this as a person's initials rather than a leave type indicator.
3. The "Export" button in the header performs no action visible to the user (it navigates to a page but shows no feedback) — the `window.nuToast` call was not wired in this component.

**Specific Code Improvements:**

| Issue | File | Line | Fix |
|---|---|---|---|
| Ring chart labels lack tooltip with leave type name + policy | `leave/page.tsx` | L263–289 | Wrap each Ring in a Mantine `Tooltip` with content showing `type.leaveName`, opening balance, and accrual details |
| LeaveAvatar semantics: initials of leave type name read as person | `leave/page.tsx` | L202–217 | Replace initials with a colored dot (`w-3 h-3 rounded-full`) using `RING_COLORS[i]` — no initials needed since the leave name is shown adjacent |
| Empty balance state has no CTA | `leave/page.tsx` | L258–259 | Add link text "Contact HR to set up your leave plan" below the empty message |

**Priorities:** Ring tooltip = High, LeaveAvatar semantics = Medium, Empty CTA = Medium

### Page 3: Payroll (`/payroll/page.tsx`)

**Visual Hierarchy Quality: 8/10**
Strong. Page header with run name + contextual subtitle establishes context immediately. The current-run banner with gradient background and pipeline stepper is the primary focal point. KPI row (4 cards) follows naturally. The cost-by-run table + pay composition donut side-by-side creates a good analytical view. Run history table at the bottom is a sensible "show all" pattern.

**Information Density: Right (slightly dense for first-time users)**
The three `BannerFigure` stats (Gross, Net pay, Taxes & deductions) in the banner are prominent. The pipeline stepper is visually clear. For a finance admin with context, this is excellent density. For a new admin doing their first run, the distinction between "Processed" and "Approved" in the pipeline may be unclear.

**Navigation Clarity: 9/10**
Three header CTAs (Export, Configure, Run Payroll) are correctly ordered by frequency of use. `Run Payroll` as the primary variant draws the eye correctly. The `PermissionGate` wrapping correctly hides "Run Payroll" from read-only users. The "Review & approve" button on the banner closes the loop from status to action.

**Empty/Loading/Error State Quality: 9/10**
`BannerSkeleton` and `KpiSkeleton` match the layout with high fidelity. `EmptyBanner` for no active cycle is well-structured with icon + description + CTA. `ErrorBanner` uses `role="alert"`. Minor: the `EmptyBanner` does not show placeholder KPI cards (which would give new admins a sense of what to expect after running payroll).

**Mobile Responsiveness: 6/10**
The run history table has `min-w-[760px]` and relies on `overflow-x-auto` scroll — acceptable but the table on mobile shows no sticky first column (run name) making horizontal scroll context-losing. The cost-by-run table also has `min-w-[480px]`. The banner pipeline stepper uses `flex-wrap` but on 375px the 5 steps stack in confusing ways.

**Enterprise-Grade Feel: 9/10**
The gradient banner with mono-spaced currency figures is visually premium. The pipeline stepper (numbered dots → check icons for completed steps) mirrors Stripe's payment flow UX. The Donut chart legend is clean. This page competes with Rippling's payroll overview.

3. The `BannerFigure` label "Taxes & deductions" uses an HTML entity (`&amp;`) that will render correctly in the browser but will be confusing if this text is ever serialized or sent to an email template.

**Specific Code Improvements:**

## Global Recommendations

### Navigation: Sidebar

**Current state:** Shell uses `ProductRail` + `NavPanel` + `TopBar` three-component structure. The sidebar correctly has max one level of sub-menus. RBAC-aware via `usePermissions` with `PermissionGate`. Approval inbox count badge wired via `useApprovalInboxCount`.

**Improvements:**
1. Add keyboard shortcut display: per the design spec, `?` should open a local shortcuts modal — this is not implemented. The `CommandPalette` (`Cmd+K`) is wired, but `?` is not.
2. Sidebar collapse should persist in `localStorage` / Zustand store across sessions — currently resets on reload based on `useUiStore` hydration timing.
3. The product rail (NU-HRMS, NU-Hire, NU-Grow, NU-Fluence) switches correctly but does not indicate unread notifications per product (only the overall bell count in the top bar is shown).
4. Deep-link breadcrumbs are missing on 5 pages that pass `showBreadcrumbs={false}` without explaining why — employee dashboard is one, but its parent navigation context (Home > My Dashboard) would improve orientation.

### Dashboard: KPI Hierarchy

**Recommended layout standard for all dashboard pages:**
- Row 1: 4 KPI stat cards (using `Stat` with `iconTone`, `delta`, `deltaDir`)
- Row 2: Primary chart (2/3 width) + secondary widget (1/3 width)
- Row 3: Data table (full width, sticky header)

The Employee Dashboard, Payroll page, and Manager Dashboard follow this pattern to different degrees. Several other dashboards (executive, analytics) deviate. Standardizing the row-count approach would reduce design decisions per page.

**Missing KPI on Employee Dashboard:** "Next payday" date — a one-liner from the payroll API would be high-value for employees and is already available.

### Forms: Multi-step Patterns

**Current state:** The design system spec calls for stepped wizards with local draft saving. This is implemented for onboarding (`onboarding/` routes) but not for other long forms (leave application, expense claim creation, contract setup).

**Recommendations:**
1. Leave apply form (`/leave/apply`) should use a 3-step wizard: Step 1 (Leave type + dates + duration preview), Step 2 (Reason + supporting document upload), Step 3 (Review + submit). Currently it is a single-page form which is acceptable but loses the progress affordance.
2. All forms should persist draft state to `localStorage` using the pattern from `IdempotencyService` key namespacing — currently form data is lost on accidental navigation.
3. Slide-out panels (drawers) should be the default for edit operations on list pages. Currently some pages use centered modals for edits, which the design spec explicitly recommends against.

### Tables: Power-User Features

Per the design spec, the following should be present on all data tables with 20+ expected rows:
- Sticky header (currently absent on most tables — only 46 uses of `sticky` class found across all tsx files including non-table uses)
- Sticky first column for employee name / ID (not implemented anywhere)
- Bulk action floating bar (implemented via `DataTable` component but not wired to all tables)
- Column visibility toggle (present in `AdvancedFilterPanel` but not surfaced on all admin tables)

**Quick fix available:** The `tailwind-presets.ts` already defines `table.headerSticky: 'sticky top-0 z-10 bg-[var(--bg-card)]'` — it just needs to be applied to table headers. This is a copy-paste change across ~20 admin table pages.

### QW2 — Employee Dashboard: Add today's attendance status indicator (45 min)

**File:** `frontend/app/dashboards/employee/page.tsx` lines 197–215
**Change:** After the header `<h1>`, check if `data.attendanceSummary.recentHistory[0].date` matches today's ISO date. If yes, show a green chip "Clocked in · In: HH:MM". If no, show a yellow chip "Not yet marked today".

```tsx
// After line 214 (the header div close tag):
{(() => {
  const today = new Date().toISOString().split('T')[0];
  const todayRecord = data.attendanceSummary.recentHistory.find(
    (r) => r.date.startsWith(today)
  );
  if (!todayRecord) return (
    <span className="inline-flex items-center gap-1.5 px-2.5 py-1 text-xs font-medium rounded-full bg-warning-100 text-warning-700 dark:bg-warning-900/40 dark:text-warning-300">
      <Clock className="h-3 w-3" /> Not yet marked today
    </span>
  );
  if (todayRecord.checkInTime) return (
    <span className="inline-flex items-center gap-1.5 px-2.5 py-1 text-xs font-medium rounded-full bg-success-100 text-success-700 dark:bg-success-900/40 dark:text-success-300">
      <CheckCircle className="h-3 w-3" /> Clocked in · In: {formatTime(todayRecord.checkInTime)}
    </span>
  );
  return null;
})()}
```

**Impact:** Eliminates the #1 first-time user confusion. Employees no longer need to scan the history table to know their attendance status.

### QW5 — All pages: Move `window.nuToast` calls to be server-response-gated (90 min)

**Scope:** 11 files call `window.nuToast` inline on button click handlers before server confirmation.

**File examples:**
- `payroll/page.tsx` line 274, line 343
- `leave/page.tsx` line 299

**Pattern fix:** Replace inline onClick toasts with mutation `onSuccess` / `onError` callbacks:

```tsx
// Before (payroll/page.tsx L274):
onClick={() => window.nuToast?.('Payroll run started', {msg: 'Cycle is now calculating.', type: 'info'})}

// After — remove onClick toast; in the useMutation hook for starting a run:
onSuccess: () => {
  window.nuToast?.('Payroll run started', {msg: 'Cycle is now calculating.', type: 'info'});
},
onError: (err) => {
  window.nuToast?.('Failed to start run', {msg: err.message, type: 'error'});
},
```

**Impact:** Eliminates misleading success feedback when server operations fail. Adds error feedback that currently does not exist for these actions. Critical for user trust in financial workflows.
