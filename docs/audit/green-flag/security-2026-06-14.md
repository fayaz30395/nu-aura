## Verified-Safe (no findings)

- **SQL injection:** The only native queries (`FluenceContentRetriever.searchWikiByBodyText/searchBlogByBodyText`, lines 211-254) are fully parameterized (`:tenantId`, `:keyword`, `:lim` via `setParameter`); the Java `+` only concatenates a static SQL template. No `Statement`/string-interpolated SQL or `@Query` with `+ userInput` found. JPA + `:named` params throughout.
- **XSS sinks:** All 9 functional `dangerouslySetInnerHTML` call sites wrap content in a sanitizer (`sanitizeHtml` / `sanitizeEmailHtml` / `sanitizeAnnouncementHtml`), including `fluence/search/page.tsx:623`. The `layout.tsx:55` theme script uses a CSP `nonce`. No raw unsanitized Tiptap output rendered.
- **AuthN/Z:** Login goes through Spring `AuthenticationManager` + bcrypt cost 12; no custom crypto. Auth endpoints use an explicit permit allow-list (no `/auth/**` wildcard). Stateless sessions, 401/403 JSON entry points.
- **Rate limiting / brute force:** Auth endpoints throttled (prod 10/min, base 5/min), export endpoints 5/5min, Redis-backed `DistributedRateLimiter` + `AccountLockoutService` 5/15min. All `enabled:true` in prod (application-prod.yml:278-296).
- **Sensitive-data exposure:** Prod suppresses stack traces + messages (`include-stacktrace/message/exception: never`, application-prod.yml:193-198); Hibernate SQL/bind logging set to WARN to prevent PII leakage. No password/token/salary values logged (only recipient email addresses in notification logs — acceptable per threat model).
