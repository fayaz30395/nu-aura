# ADR-002 — Multi-tenancy via PostgreSQL Row-Level Security (tenant_id + RLS, NOBYPASSRLS app role, tx-local set_config)

> Reverse-engineered ADR documenting a decision already realized in the codebase.
> See [[Architecture-Decisions]] · [[Data-Flows]] · [[Schema]] · [[Security-Audit]].

## Status

**Accepted** — implemented, hardened to fail-closed, and guarded by a startup
canary. Verified against `backend/.../common/config/TenantRlsTransactionManager.java`,
`common/config/TenantAwareDataSourceConfig.java`, `common/security/TenantContext.java`,
`common/security/RlsStartupProbe.java`, and migrations `V177__strict_tenant_rls_policies.sql`,
`V254__enforce_runtime_rls_fail_closed.sql`.

## Context

NU-AURA is **shared-database / shared-schema**: every tenant (company) shares one
PostgreSQL 16 database with ~343 distinct tables, and every tenant-aware table carries
`tenant_id UUID NOT NULL` ([[System-Overview]]). A single forgotten
`WHERE tenant_id = ?` clause anywhere in ~258 services would leak one company's HR
data to another — an unacceptable failure for payroll, performance, and PII data.

Application-layer filtering alone is too fragile to be the only line of defense. The
platform needed **defense-in-depth tenant isolation at the database engine itself**,
plus a guarantee that pooled connections never carry stale tenant context between
requests.

## Decision

Enforce tenant isolation in **two cooperating layers**:

1. **Application layer (Layer 1)** — `TenantContext` is a `ThreadLocal<UUID>`
   populated per request by `TenantFilter` (and re-asserted by
   `JwtAuthenticationFilter` from the JWT claim, which is authoritative over the
   `X-Tenant-ID` header). Service code calls `TenantContext.requireCurrentTenant()`
   to fail fast when context is missing.

2. **Database layer (Layer 2, PostgreSQL RLS)** —
   `TenantRlsTransactionManager` (a `JpaTransactionManager` registered primary in
   `JpaConfig`) overrides `doBegin()` to run
   `SELECT set_config('app.current_tenant_id', ?, true)` right after each
   transaction starts. The third argument `true` makes it **transaction-local
   (`SET LOCAL`)**, so it auto-reverts on commit/rollback. The UUID is passed as a
   **bound parameter**, never string-concatenated (CRIT-002 — prevents injection
   into `set_config`). When no tenant is bound, it explicitly `RESET`s.
   `doCleanupAfterCompletion` `RESET`s again before the connection returns to the
   pool. `TenantAwareDataSourceConfig` covers non-JPA/autocommit paths by wrapping
   HikariCP `getConnection()`/`close()` to set and reset the GUC.

RLS policies read `current_setting('app.current_tenant_id', true)::uuid`.

**Fail-closed hardening** (`V254`): the runtime DB role is **`NOBYPASSRLS`** (and
non-superuser, since PostgreSQL superusers bypass RLS), so an unset/empty tenant GUC
returns **zero rows** rather than everything. `V177` removed the old permissive
`OR current_setting(...) IS NULL` fallback. Flyway DDL runs under a separate
**`BYPASSRLS` migration role**. `RlsStartupProbe` is a boot-time canary: it opens a
connection without tenant context and asserts `SELECT COUNT(*) FROM employees`
returns 0, failing startup if the policy regresses.

## Consequences

### Positive

- **Database-enforced isolation** — even a service with a missing tenant filter
  cannot read another tenant's rows; RLS is the backstop.
- **No cross-request leakage** — `SET LOCAL` + explicit reset on cleanup and on
  connection close closes the pooled-connection leak vector twice over.
- **Fail-closed by default** — `NOBYPASSRLS` + strict policies mean the safe failure
  mode is "no data," not "all data."
- **Regression-proof boot** — `RlsStartupProbe` turns a silent policy regression into
  a loud startup failure.

### Negative

- **Operational coupling to roles** — correctness depends on the runtime role being
  non-superuser `NOBYPASSRLS` and the migration role being `BYPASSRLS`; a
  misconfigured DB user silently weakens or breaks the model.
- **Every JPA path must go through the custom tx manager** — non-JPA/autocommit work
  needs `TenantAwareDataSourceConfig`; a raw `DataSource` bypass would skip the GUC.
- **Connection-pool reasoning required** — engineers must understand `SET LOCAL`
  semantics and pooling to avoid introducing leaks (documented in
  `TenantRlsTransactionManager.java` warnings).

## Alternatives Considered

- **Application-layer filtering only** (`WHERE tenant_id = ?` / Hibernate filters) —
  rejected as sole control: one missed clause leaks data; kept as Layer 1 only.
- **Schema-per-tenant or database-per-tenant** — rejected: thousands of schemas/DDLs,
  costly migrations across 293 Flyway versions (V0–V304), and connection-pool fan-out.
- **Permissive RLS with NULL-tenant fallback** — was the original model; replaced by
  `V177`/`V254` because a NULL tenant read everything (fail-open).
